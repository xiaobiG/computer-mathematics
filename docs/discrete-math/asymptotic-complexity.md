# 渐进复杂度：算法规模如何影响时间

## 先问一个问题

一个程序在你的电脑上很快，不表示它面对十倍或百万倍数据仍然可用。复杂度研究输入规模 $n$ 变大时，资源消耗的增长率。

## 三个记号

- $O(f(n))$：增长不会超过常数倍的 $f(n)$；
- $\Omega(f(n))$：增长至少达到常数倍的 $f(n)$；
- $\Theta(f(n))$：上下界同阶。

忽略常数和低阶项不是说它们不重要，而是在大规模下先抓住决定性的增长趋势。例如 $3n^2+10n$ 是 $\Theta(n^2)$。

## 常见增长率

| 复杂度 | 典型例子 |
| --- | --- |
| $O(1)$ | 数组按索引读取 |
| $O(\log n)$ | 二分查找 |
| $O(n)$ | 扫描数组 |
| $O(n\log n)$ | 归并排序 |
| $O(n^2)$ | 两层全量配对 |
| $O(2^n)$ | 枚举全部子集 |

## 不要只数循环层数

嵌套循环不必然是 $O(n^2)$。若内层总迭代次数被摊还限制，复杂度可能更低；反之，递归也可能是指数级。应当写出总操作次数再化简。

## 练习

分析双指针寻找有序数组两数之和的复杂度，并解释为什么它不是 $O(n^2)$。
