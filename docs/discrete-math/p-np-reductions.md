# P、NP 与归约：验证为什么不等于快速求解

## 学习目标

读完后，你能把问题写成判定问题；区分“候选解验证快”与“必能快速找到解”；写出多项式时间归约的方向；解释 NP 完全的含义；运行一个 3-SAT 验证器和独立集到 CNF-SAT 的归约；并避免把 `NP`、NP 完全与“目前没有算法”混为一谈。

## 从一个排程问题开始

给定一组带冲突约束的课程，问“是否存在一个满足所有约束的排程？”这是**判定问题**：答案只有是或否。若同事交来一份具体排程，逐条检查冲突和容量通常很快；但从空白开始找一份排程可能要探索大量组合。

这正是 NP 的起点。它不是“难问题”的同义词，更不代表“不可能在多项式时间解决”。它描述一个关于**可验证性**的类别；$P\mathrel{?=}NP$ 至今仍是未解决的数学问题。

## 严格定义：输入长度与判定语言

令 $|x|$ 为输入编码长度。判定问题可看作字符串集合（语言）$L$：输入 $x$ 在 $L$ 中表示答案“是”。

- $P$：存在确定性算法，在 $|x|$ 的多项式时间内判定 $x\in L$。
- $NP$：存在多项式 $p$ 和验证器 $V$，使得

$$x\in L\iff\exists w,\ |w|\le p(|x|)\ \text{且}\ V(x,w)=1,$$

且 $V$ 的运行时间是 $|x|+|w|$ 的多项式。$w$ 称为证书或 witness。

因此 $P\subseteq NP$：若能快速判定，验证器忽略证书直接运行判定算法即可。反向包含是否成立未知。这里的 N 是 nondeterministic（非确定性计算模型），不是“non-polynomial”。

## 3-SAT：验证器的最小实现

3-SAT 的输入是合取范式，每个子句最多含三个文字，如

$$F=(x_1\lor\neg x_2\lor x_3)\land(\neg x_1\lor x_2)\land x_3.$$

一个证书是每个变量的真值。验证器只须扫描每个子句，判断是否至少有一个文字为真：若公式有 $m$ 个子句、文字总数为 $M$，验证是 $O(M)$。项目实现刻意将“验证”和“搜索”分开：

```python
from projects.algorithm_lab.sat_verifier import find_satisfying_assignment, verify_assignment

formula = ((1, -2, 3), (-1, 2), (3,))
witness = find_satisfying_assignment(formula, max_variables=20)  # 教学基线：枚举至多 2^20 种赋值
assert witness is not None
assert verify_assignment(formula, witness)      # 验证只扫描文字
```

运行测试：

```bash
python -m unittest projects.algorithm_lab.test_sat_verifier
```

穷举器会对 $n$ 个变量尝试 $2^n$ 个赋值，故最坏情况为 $O(2^nM)$；这**不是** 3-SAT 必然不能更快解决的证明，只是一个明确且可审计的上界。`max_variables` 是教学资源契约：超过上限会拒绝，而不是悄悄开始一次不可控的指数搜索；它既不证明 SAT 困难，也不改变上限内实例的 yes/no 结果。现代 SAT 求解器使用传播、学习与启发式，许多真实实例远快于枚举，但最坏情形仍是研究核心。

## 归约：把一个问题的求解器变成另一个问题的求解器

对判定问题 $A,B$，多项式时间 many-one 归约写作 $A\le_p B$，意为存在多项式时间函数 $f$，满足

$$x\in A\iff f(x)\in B.$$

方向至关重要：若 $A\le_p B$ 且 $B\in P$，则 $A\in P$，因为可先算 $f(x)$，再运行 $B$ 的算法。故要说明 $B$ 至少和 $A$ 一样难，应从已知困难的 $A$ **归约到** $B$，不是反过来。

以 3-SAT 到排程为例，构造会为变量创建“真/假”选择，为子句创建“至少一个选择被满足”的约束。你必须证明两向：

1. 若原公式可满足，可由其赋值构造一个合法排程；
2. 若构造后的排程合法，可从中读出满足原公式的赋值；
3. 构造规模和时间都至多是原输入的多项式。

缺任一方向，都是“看起来像”的转换，尚不是归约证明。

## 分步推导与可运行归约：独立集如何编码成 CNF-SAT

“归约方向”最容易在纸面上被说对、在构造时却写反。下面把一个具体判定问题写成公式：给定无向图 $G=(V,E)$ 与整数 $k$，是否存在大小至少 $k$ 的独立集（任意两点之间没有边）？对 `slot=0,...,k-1` 和每个顶点 $v$，建立布尔变量 $x_{slot,v}$，表示“这个槽位选择 $v$”。构造三类子句：

1. 每个槽位至少选一个顶点：$\bigvee_{v\in V}x_{slot,v}$；
2. 同一槽位至多选一个顶点，并且不同槽位不可重复同一顶点；
3. 若 $(u,v)\in E$，不同槽位不能分别选 $u,v$。

第二、三类都是二文字的否定析取，例如 $\neg x_{i,u}\lor\neg x_{j,v}$。因此任何满足赋值都会从每个槽位读出一个不同、互不相邻的顶点；反过来，任意独立集可填入槽位并满足所有子句。构造使用 $k|V|$ 个变量和多项式数量的子句，所以

$$\text{Independent Set}\le_p\text{CNF-SAT}.$$

注意这里刻意归约到一般 CNF-SAT，而不是声称已经完成 CNF-SAT 到 3-SAT 的 gadget 构造；后者还需用辅助变量把长子句拆成等价的三文字链。

```python
from projects.algorithm_lab.sat_verifier import (
    independent_set_cnf_certificate,
    independent_set_cnf_report,
)

vertices = ["a", "b", "c", "d"]
edges = [("a", "b"), ("b", "c"), ("c", "d")]
report = independent_set_cnf_report(vertices, edges, 2)

assert report["cnf_satisfiable"]
assert report["small_instance_independent_set_oracle"]
assert report["yes_no_agree"]
assert len(report["decoded_independent_set"]) == 2
assert independent_set_cnf_certificate(vertices, edges, 2, report)
```

报告保存图、$k$、构造出的 CNF、变量/子句数量、SAT 枚举得到的槽位选择，以及一个只用于小图的独立集枚举 oracle。两边均为 yes 或均为 no，才说明这次有限实例的构造与解码没有写反。证书从原图重建公式、重新枚举 SAT 和独立集；篡改一个子句数、公式或解码集合都会失败。

这个实验并**不**以小图穷举证明归约定理或 NP 完全性：它只检查一组可读的构造不变量。`max_variables` 仍是教学资源上限；真实归约的多项式性来自变量与子句数关于 $|V|,|E|,k$ 的代数计数，而不是一次成功运行。

## NP 完全与工程含义

若问题 $B$ 同时满足 $B\in NP$，且每个 $A\in NP$ 都有 $A\le_p B$，则 $B$ 是 NP 完全。若某个 NP 完全问题进入 $P$，则所有 NP 问题进入 $P$；若证明某个 NP 问题不在 $P$，则 $P\ne NP$。这解释了为何 3-SAT、独立集、旅行商**判定版**等问题在理论中居中，但不能替代对具体实例的性能测量。

工程中遇到 NP 完全问题，常见可验证策略是：限定参数或图结构、使用近似算法、启发式、分支定界、SAT/ILP 求解器，或只在小规模上精确枚举。选择依据应是实例规模、最坏情况风险、可接受误差和可解释性，而非“NP 完全所以放弃”。

## 失败案例与工程边界

- **优化版与判定版混淆**：$P/NP$ 定义面向判定问题；优化问题需先说明其阈值判定版本或比较函数问题复杂度。
- **错误的归约方向**：$B\le_p A$ 只能说明 $B$ 不比 $A$ 难，不能把 $B$ 证明成困难。
- **把小输入实验当理论结论**：穷举 20 个变量成功，不代表 200 个变量可行，更不证明复杂度下界。
- **证书过长或无法验证**：NP 需要多项式长度证书及多项式验证；“答案存在”本身不够。
- **把 CNF-SAT 误写成 3-SAT**：长析取子句还未自动成为 3-CNF；必须额外给出保持可满足性的辅助变量构造。

## 常见误区

1. “NP 就是非多项式时间。”错误：NP 指可在多项式时间验证候选解。
2. “NP 完全问题在实践中都无法解决。”错误：结构化实例和高质量求解器常能处理很大规模，最坏情况保证仍不同。
3. “归约就是把问题翻译一下。”错误：必须有多项式构造和 yes/no 双向等价证明。
4. “P 不等于 NP 已被证明。”错误：截至目前这仍是开放问题。

## 练习

1. **基础题**：说明为何所有 $P$ 问题也属于 $NP$，并明确验证器如何使用空证书。
2. **推导题**：证明若 $A\le_pB$ 且 $B\in P$，则 $A\in P$；标出两段算法的总复杂度。
3. **编码题**：改变 `find_satisfying_assignment` 的 `max_variables`，观察超限时的异常；测试该保护不会改变上限内小公式答案。
4. **开放题**：为一个课程排程系统设计“精确求解、近似/启发式、人工回退”的决策规则，并写明哪些指标触发回退。
5. **归约题**：为 `Independent Set` 到 CNF-SAT 构造写出“独立集 $\Rightarrow$ 满足赋值”和“满足赋值 $\Rightarrow$ 独立集”的两段证明；指出为何同一顶点的槽位互斥不可省略。

## 练习答案提示

1. 对任意 $P$ 问题，验证器直接运行其多项式时间判定算法并忽略空证书；证书长度为 0，仍满足 NP 定义。
2. 先用归约在多项式时间构造 $f(x)$，再运行 $B$ 的多项式算法；yes/no 双向等价保证输出正确，两段多项式时间相加/复合仍为多项式。
3. 上限是教学枚举器的资源契约，不是复杂度证明；测试上限内的可满足与不可满足公式保持原结果，并断言超限异常。
4. 将规模、时限、冲突率和可接受最优性差距写成明确阈值；回退时保留不可行/超时证据与人工可修改的约束解释。
5. 前向方向按独立集成员填槽，其余变量为假；反向方向由每槽至少一个/至多一个读出顶点，再由重复与边排斥子句证明它们互异且不相邻。若省略重复排斥，同一顶点可占多个槽位，SAT 的 yes 将不再保证大小为 $k$ 的集合。
