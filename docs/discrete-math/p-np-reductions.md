# P、NP 与归约：验证为什么不等于快速求解

## 学习目标

读完后，你能把问题写成判定问题；区分“候选解验证快”与“必能快速找到解”；写出多项式时间归约的方向；解释 NP 完全的含义；运行一个 3-SAT 验证器；并避免把 `NP`、NP 完全与“目前没有算法”混为一谈。

## 从一个排程问题开始

给定一组带冲突约束的课程，问“是否存在一个满足所有约束的排程？”这是**判定问题**：答案只有是或否。若同事交来一份具体排程，逐条检查冲突和容量通常很快；但从空白开始找一份排程可能要探索大量组合。

这正是 NP 的起点。它不是“难问题”的同义词，更不代表“不可能在多项式时间解决”。它描述一个关于**可验证性**的类别；$P\mathrel{?=}NP$ 至今仍是未解决的数学问题。

## 严格定义：输入长度与判定语言

令 $|x|$ 为输入编码长度。判定问题可看作字符串集合（语言）$L$：输入 $x$ 在 $L$ 中表示答案“是”。

- $P$：存在确定性算法，在 $|x|$ 的多项式时间内判定 $x\in L$。
- $NP$：存在多项式 $p$ 和验证器 $V$，使得

$$x\in L\iff\exists w,\ |w|\le p(|x|)\ \text{且}\ V(x,w)=1,$$

且 $V$ 的运行时间是 $|x|+|w|$ 的多项式。$w$ 称为证书或 witness。

因此 $P\subseteq NP$：若能快速判定，验证器忽略证书直接运行判定算法即可。反向包含是否成立未知。这里的 N 是 nondeterministic（非确定性计算模型），不是“non-polynomial”。

## 3-SAT：验证器的最小实现

3-SAT 的输入是合取范式，每个子句最多含三个文字，如

$$F=(x_1\lor\neg x_2\lor x_3)\land(\neg x_1\lor x_2)\land x_3.$$

一个证书是每个变量的真值。验证器只须扫描每个子句，判断是否至少有一个文字为真：若公式有 $m$ 个子句、文字总数为 $M$，验证是 $O(M)$。项目实现刻意将“验证”和“搜索”分开：

```python
from projects.algorithm_lab.sat_verifier import find_satisfying_assignment, verify_assignment

formula = ((1, -2, 3), (-1, 2), (3,))
witness = find_satisfying_assignment(formula)  # 教学基线：枚举 2^n 种赋值
assert witness is not None
assert verify_assignment(formula, witness)      # 验证只扫描文字
```

运行测试：

```bash
python -m unittest projects.algorithm_lab.test_sat_verifier
```

穷举器会对 $n$ 个变量尝试 $2^n$ 个赋值，故最坏情况为 $O(2^nM)$；这**不是** 3-SAT 必然不能更快解决的证明，只是一个明确且可审计的上界。现代 SAT 求解器使用传播、学习与启发式，许多真实实例远快于枚举，但最坏情形仍是研究核心。

## 归约：把一个问题的求解器变成另一个问题的求解器

对判定问题 $A,B$，多项式时间 many-one 归约写作 $A\le_p B$，意为存在多项式时间函数 $f$，满足

$$x\in A\iff f(x)\in B.$$

方向至关重要：若 $A\le_p B$ 且 $B\in P$，则 $A\in P$，因为可先算 $f(x)$，再运行 $B$ 的算法。故要说明 $B$ 至少和 $A$ 一样难，应从已知困难的 $A$ **归约到** $B$，不是反过来。

以 3-SAT 到排程为例，构造会为变量创建“真/假”选择，为子句创建“至少一个选择被满足”的约束。你必须证明两向：

1. 若原公式可满足，可由其赋值构造一个合法排程；
2. 若构造后的排程合法，可从中读出满足原公式的赋值；
3. 构造规模和时间都至多是原输入的多项式。

缺任一方向，都是“看起来像”的转换，尚不是归约证明。

## NP 完全与工程含义

若问题 $B$ 同时满足 $B\in NP$，且每个 $A\in NP$ 都有 $A\le_p B$，则 $B$ 是 NP 完全。若某个 NP 完全问题进入 $P$，则所有 NP 问题进入 $P$；若证明某个 NP 问题不在 $P$，则 $P\ne NP$。这解释了为何 3-SAT、独立集、旅行商**判定版**等问题在理论中居中，但不能替代对具体实例的性能测量。

工程中遇到 NP 完全问题，常见可验证策略是：限定参数或图结构、使用近似算法、启发式、分支定界、SAT/ILP 求解器，或只在小规模上精确枚举。选择依据应是实例规模、最坏情况风险、可接受误差和可解释性，而非“NP 完全所以放弃”。

## 失败案例与工程边界

- **优化版与判定版混淆**：$P/NP$ 定义面向判定问题；优化问题需先说明其阈值判定版本或比较函数问题复杂度。
- **错误的归约方向**：$B\le_p A$ 只能说明 $B$ 不比 $A$ 难，不能把 $B$ 证明成困难。
- **把小输入实验当理论结论**：穷举 20 个变量成功，不代表 200 个变量可行，更不证明复杂度下界。
- **证书过长或无法验证**：NP 需要多项式长度证书及多项式验证；“答案存在”本身不够。

## 常见误区

1. “NP 就是非多项式时间。”错误：NP 指可在多项式时间验证候选解。
2. “NP 完全问题在实践中都无法解决。”错误：结构化实例和高质量求解器常能处理很大规模，最坏情况保证仍不同。
3. “归约就是把问题翻译一下。”错误：必须有多项式构造和 yes/no 双向等价证明。
4. “P 不等于 NP 已被证明。”错误：截至目前这仍是开放问题。

## 练习

1. **基础题**：说明为何所有 $P$ 问题也属于 $NP$，并明确验证器如何使用空证书。
2. **推导题**：证明若 $A\le_pB$ 且 $B\in P$，则 $A\in P$；标出两段算法的总复杂度。
3. **编码题**：为 `find_satisfying_assignment` 加入变量数上限，超限时抛出异常；测试该保护不会改变小公式答案。
4. **开放题**：为一个课程排程系统设计“精确求解、近似/启发式、人工回退”的决策规则，并写明哪些指标触发回退。
