# Diffie–Hellman 密钥交换：同一秘密为何不能证明“你是谁”

## 学习目标

读完后，你能从交换律推导 DH 共享秘密；区分“求私钥”“计算共享秘密”“区分共享秘密是否随机”三类安全假设；实现仅教学用途的小群模拟；并能精确说明未经认证的 DH 为何必然遭受中间人攻击。

## 问题：公开信道上先有秘密，还是先有身份？

Alice 与 Bob 可以公开传输任何字节，却想得到攻击者不知道的会话密钥。直接发送密钥毫无意义；DH 的巧妙之处是双方各自留下一个私有指数，使窃听者看到的公开值无法直接组合出同一结果。

但这只解决“被动窃听者”问题。若 Mallory 能替换消息，Alice 与 Bob 会分别与 Mallory 建立两个看似正常的秘密，且彼此都不知道对方从未参与同一轮交换。

## 严格对象：不要把小质数例子当作安全群

教学版可在乘法群 $\mathbb{Z}_p^*$ 中工作：公开大素数 $p$ 和某个子群生成元 $g$，子群阶为大素数 $q$。生产协议通常用经过审计的椭圆曲线群和固定安全参数。

Alice 取均匀随机私钥 $a\in\{1,\ldots,q-1\}$，发送 $A=g^a$；Bob 取 $b$，发送 $B=g^b$，所有运算在群中进行。两者计算

$$K_A=B^a=(g^b)^a=g^{ab}=(g^a)^b=A^b=K_B.$$

等式来自指数乘法可交换，不来自“加密”。把 $K$ 直接当 AES 密钥也是错误的：须用 KDF 连同上下文、双方公开值和协议标签导出多个密钥。

## 三个常被混淆的困难问题

给定 $g,g^a,g^b$：

- **DLP**：求 $a$；
- **CDH**：计算 $g^{ab}$；
- **DDH**：区分元组 $(g,g^a,g^b,g^{ab})$ 与 $(g,g^a,g^b,g^c)$。

在一些群中，DLP 难通常意味着 CDH 不易，但逻辑上是不同问题；协议的密钥不可区分性更接近 DDH（或随机预言机/KDF 下的相关假设）。工程讨论必须写清使用的是哪一个假设、在哪个群内成立，而不是笼统地说“离散对数很难”。

## 可运行实验：数学正确不代表安全

```python
def dh_public(g: int, private: int, p: int) -> int:
    if not (1 < g < p and 0 < private < p - 1):
        raise ValueError("参数不在教学群的范围内")
    return pow(g, private, p)

def dh_shared(peer_public: int, private: int, p: int) -> int:
    # 真实协议还必须做子群/曲线点验证并经 KDF 导出密钥。
    if not 1 < peer_public < p - 1:
        raise ValueError("拒绝平凡或范围外的对端公钥")
    return pow(peer_public, private, p)

p, g = 23, 5                 # 极小参数：只用于手算和测试
a, b = 6, 15
A, B = dh_public(g, a, p), dh_public(g, b, p)
assert dh_shared(B, a, p) == dh_shared(A, b, p)
```

`pow` 的重复平方复杂度为 $O(\log q)$ 次群乘法。安全私钥不是“任取一个整数”：必须来自密码学安全随机源，长度和群阶必须满足目标安全级别，且私钥应是一次性的临时值以获得前向保密。

## 中间人攻击的逐步推演

Mallory 选择 $m_A,m_B$：把 Alice 的 $A$ 替换为 $M_A=g^{m_A}$ 发给 Bob，把 Bob 的 $B$ 替换为 $M_B=g^{m_B}$ 发给 Alice。

$$K_{A,M}=M_B^a,\qquad K_{M,A}=A^{m_B};$$

$$K_{B,M}=M_A^b,\qquad K_{M,B}=B^{m_A}.$$

每对都相等，故 Mallory 能解密 Alice 的消息、篡改后再用另一把密钥加密给 Bob。双方从“共享秘密相同”推不出“秘密是与预期身份共享的”。

认证需要额外机制：TLS 使用证书签名或 PSK 绑定握手转录；Signal 类协议使用身份密钥和密钥确认；人类配对可显示短认证字符串。仅给 DH 消息加一个未认证哈希，仍不能阻止攻击者替换整段对话。

## 失败案例与工程边界

- **小子群/无效公钥攻击**：若不验证对端公钥所属群，攻击者可让共享值落入小集合，从多次响应中恢复私钥的同余信息。
- **重用临时私钥**：泄露一次私钥会危及更多会话；长期静态 DH 还改变前向保密性质。
- **直接使用共享整数**：原始群元素有偏、没有绑定协议上下文；使用标准 KDF 和密钥确认。
- **自制协议**：没有消息顺序、身份、重放和降级防护的“DH + 对称加密”不是安全通信协议。

## 常见误区

1. “双方同算出 $K$，就认证了身份。”错误：中间人也能分别算出两个 $K$。
2. “公开 $g^a$ 会泄露 $a$。”错误：安全性正依赖在选定群内难以反求离散对数；小群例外。
3. “DH 自带加密。”错误：它只产生共享材料，保密消息还需 KDF、AEAD、认证与状态机。
4. “检查 $1<Y<p-1$ 就足够。”错误：真实有限域/椭圆曲线还要做子群或点验证。

## 练习

1. **基础题**：在 $p=23,g=5,a=6,b=15$ 下手算 $A,B,K$，验证两端一致。
2. **推导题**：用上面的四个等式写出 Mallory 如何分别与 Alice、Bob 共享不同密钥，并指出双方各自看到的异常为何为零。
3. **编码题**：扩展示例模拟中间人转发和篡改一条“消息”；加入一个事先共享的 MAC 后，断言篡改会被发现（这仍只是教学模型）。
4. **开放题**：阅读 TLS 1.3 的握手转录绑定概念，说明证书签名、密钥确认、前向保密分别解决哪个威胁。
