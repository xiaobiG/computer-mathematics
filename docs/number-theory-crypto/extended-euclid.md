# 扩展欧几里得与模逆元：模运算中何时可以“除法”

## 文章元信息

- **前置知识**：整除、余数、[模运算与快速幂](/number-theory-crypto/modular-arithmetic)

## 学习目标

- 用贝祖等式判断模逆元是否存在；
- 实现扩展欧几里得算法并验证系数；
- 解释 RSA 与 CRT 中为什么需要互素条件。

## 从一个计算问题开始

普通算术中 $3x=1$ 的解是 $1/3$；模 7 下却有整数解 $x=5$，因为 $3\times5\equiv1\pmod7$。模 8 下 $2x\equiv1$ 则永远无解。程序怎样在不穷举所有 $x$ 的前提下判断并求解？

## 定义与推导

欧几里得算法利用 $\gcd(a,b)=\gcd(b,a\bmod b)$。更强的贝祖等式说存在整数 $x,y$ 使

$$ax+by=\gcd(a,b).$$

当 $\gcd(a,m)=1$，式子模 $m$ 后为 $ax\equiv1\pmod m$，因此 $x\bmod m$ 是 $a$ 的逆元。反之，若逆元存在，任何公因子都必须整除 1，所以互素也是必要条件。

## 手算轨迹：余数链怎样倒推出系数

求最大公约数的“向下走”与求贝祖系数的“向上回代”不是两套算法。以 $a=240,b=46$ 为例，先只做整除；每个余数都小于当前除数，所以最后一个非零余数就是 $\gcd(240,46)$：

| 轮次 | 除法 | 余数 |
| --- | --- | --- |
| 1 | $240=5\cdot46+10$ | $10$ |
| 2 | $46=4\cdot10+6$ | $6$ |
| 3 | $10=1\cdot6+4$ | $4$ |
| 4 | $6=1\cdot4+2$ | $2$ |
| 5 | $4=2\cdot2+0$ | $0$ |

然后从最后一个非零余数反向代入，而不是凭空猜 $x,y$：

$$
\begin{aligned}
2&=6-4\\
 &=6-(10-6)=2\cdot6-10\\
 &=2\cdot(46-4\cdot10)-10=2\cdot46-9\cdot10\\
 &=2\cdot46-9\cdot(240-5\cdot46)\\
 &=-9\cdot240+47\cdot46.
\end{aligned}
$$

因此追踪的最终结果应为 $(g,x,y)=(2,-9,47)$，且每一行都只用了表中一条已核对的除法。把这条等式除以模数的直觉是危险的；正确动作是先检查 $g=1$。例如要找 $7$ 在模 $26$ 下的逆元，余数链为 $26=3\cdot7+5$、$7=1\cdot5+2$、$5=2\cdot2+1$，回代得到

$$1=3\cdot26-11\cdot7,$$

所以 $7\cdot(-11)\equiv1\pmod{26}$，归一化后 $-11\bmod26=15$。

## 为什么递归返回的系数一定正确

递归帧 `extended_gcd(a, b)` 的规格是：返回 $(g,x,y)$，满足 $g=\gcd(a,b)$ 且 $ax+by=g$。当 $b=0$ 时，返回 $(a,1,0)$，规格直接成立。否则设商 $q=\lfloor a/b\rfloor$、余数 $r=a\bmod b$；递归假设给出

$$bx_1+ry_1=g,\qquad g=\gcd(b,r).$$

又因为 $r=a-qb$ 且 $\gcd(a,b)=\gcd(b,r)$，代入并按 $a,b$ 收集系数：

$$
g=b x_1+(a-qb)y_1=a y_1+b(x_1-qy_1).
$$

故当前帧返回 $(g,y_1,x_1-qy_1)$ 正好保持规格。这也解释了代码中看似“交换”的 `y1, x1 - (a // b) * y1`：它是上述等式的两个新系数，不是经验规则。递归参数的第二项从 $b$ 变成 $r$，并且 $0\le r<b$，所以非负课堂输入必在有限步到达基例。

## 算法实现与正确性

```python
from projects.crypto_toybox.main import (
    extended_gcd_trace,
    extended_gcd_trace_certificate,
    modular_inverse,
)

result, trace = extended_gcd_trace(240, 46)
gcd, x, y = result
assert (gcd, x, y) == (2, -9, 47)
assert 240 * x + 46 * y == gcd
assert [event.remainder for event in trace] == [10, 6, 4, 2, 0]
assert extended_gcd_trace_certificate(240, 46, result, trace)
assert modular_inverse(7, 26) == 15
assert (7 * modular_inverse(7, 26)) % 26 == 1
```

`extended_gcd_trace` 公开每次除法的被除数、除数、商和余数；上面的手算表正是它对 `(240, 46)` 的前五个事件。证书重放该链，检查每个余数确实满足 $0\le r<b$，终点为最大公约数，并独立核对 $ax+by=g$。所以它同时拒绝“余数表看似合理但不满足除法”的改动，以及“gcd 对了但回代系数错了”的改动。每轮余数严格变小，时间为 $O(\log\min(a,b))$，除保存递归栈或追踪表外，普通迭代实现可用 $O(1)$ 额外空间。

## 失败案例与工程边界

逆元不存在不是异常数值，而是代数事实：例如 $\gcd(2,8)=2$，所以 $2x\bmod8$ 永远为偶数。模数必须大于 1；负输入时应先规范化或明确 API 语义。密码代码不可据此自行构造协议，逆元计算还需考虑恒定时间和错误处理泄漏。

## 常见误区

- 模意义下的“除以 $a$”只在 $a$ 可逆时才合法。
- 逆元不是实数倒数，结果是一个同余类。
- RSA 中 $e$ 必须与 $\varphi(n)$ 互素，才能构造私钥指数 $d$。

## 练习

1. **基础**：写出 $11$ 与 $26$ 的完整余数链和回代，求 $11$ 在模 26 下的逆元。
2. **推导**：不引用贝祖等式的名字，只从一轮 $a=qb+r$ 证明欧几里得替换不改变公因子集合；再说明这为何允许递归返回正确的 $g$。
3. **调试**：有人把 `(240, 46)` 的结果写成 $(2,9,-47)$。不用运行代码，指出哪条贝祖等式失败，并解释为什么把两系数同时变号不能保持 $g$。
4. **编码**：测试负 `value`、模数 1 和不可逆输入；再篡改 `extended_gcd_trace` 的一个商而保留余数，确认追踪证书拒绝该记录。
5. **开放**：解释有限域中为何每个非零元素都有逆元，而复合模数下不一定；用零因子说明“非零”为什么不够。

## 练习答案提示

1. $26=2\cdot11+4$，$11=2\cdot4+3$，$4=1\cdot3+1$；从 $1=4-3$ 向上替换，得到 $1=3\cdot26-7\cdot11$，故逆元是 $-7\bmod26=19$。
2. $a=qb+r$ 意味着 $r=a-qb$；一个数整除 $a,b$ 当且仅当它整除 $b,r$。这保证每层返回的 gcd 未变，再与系数代入式结合就得到递归规格。
3. $240\cdot9+46\cdot(-47)=-2$，不是 $2$；同时变号会把任意 $ax+by=g$ 变为 $a(-x)+b(-y)=-g$，而 gcd 约定为非负。
4. 先定义负值是规范化后接受还是拒绝；模数 1、gcd 非 1 都没有逆元，测试应检查异常契约。商、余数和被除数必须满足 `divmod`，故即使余数未变，伪造商也应使证书失败。
5. 域的非零元素对乘法构成群，故都有逆；复合模数中存在零因子，例如 $2\cdot4\equiv0\pmod8$，因而非零元素也未必可逆。
