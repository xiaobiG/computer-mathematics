# 哈希与密码存储

哈希函数把任意长度输入映射为固定长度摘要。用于密码时，目标不是“加密后再解密”，而是验证输入是否匹配已保存的验证值。

## 正确的存储模型

对每个账户生成唯一随机盐值，将密码和盐交给专用密码 KDF（如 Argon2、scrypt 或 PBKDF2），保存盐、算法参数和派生结果。验证时以同样参数重新派生并进行安全比较。

盐能阻止不同账户相同密码产生相同结果，并使预计算彩虹表失效；KDF 的成本参数则提高离线猜测成本。

## 不要这样做

- 不要保存明文密码；
- 不要使用快速通用哈希直接存储密码；
- 不要自行设计加密或随机数方案；
- 不要将“加密密码”替代密码哈希。

## 工程边界

生产系统必须使用平台或成熟库提供的密码 API，并及时调整成本参数。本文只解释安全模型，不提供自制认证系统。

## 练习

比较“所有用户共享同一盐”与“每个用户随机盐”的攻击面；列出一个密码存储记录应包含的字段。
