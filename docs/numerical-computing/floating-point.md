# 为什么 `0.1 + 0.2 !== 0.3`

## 先问一个问题

在多数语言中，`0.1 + 0.2 === 0.3` 会得到 `false`。这不是加法坏了，而是十进制小数在二进制中经常无法有限表示。

## 二进制表示的限制

十进制的 $0.1=1/10$，分母含有因子 5；二进制有限小数只能准确表示分母约分后只含因子 2 的数。因此 $0.1$ 在二进制中会无限循环，只能被截断并舍入为附近的可表示数。

当两个近似值相加，再舍入一次，得到的值可能落在 `0.3` 所存储近似值的另一侧。

```js
0.1 + 0.2              // 0.30000000000000004
0.1 + 0.2 === 0.3      // false
```

## 正确比较方式

不要对计算结果直接使用相等判断，而是选择与问题尺度相称的容差：

```js
function nearlyEqual(a, b, epsilon = 1e-12) {
  return Math.abs(a - b) <= epsilon * Math.max(1, Math.abs(a), Math.abs(b))
}

nearlyEqual(0.1 + 0.2, 0.3) // true
```

## 工程边界

- 金额应使用最小货币单位的整数或十进制定点类型。
- 科学计算需同时考虑绝对容差与相对容差。
- 不要把浮点误差问题简化为“保留几位小数”；算法稳定性同样重要。
