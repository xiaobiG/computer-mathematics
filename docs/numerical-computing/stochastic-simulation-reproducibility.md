# 随机模拟的误差与可复现性：一次结果为什么不够

## 学习目标

读完后，你能区分抽样误差、浮点舍入误差和实现错误；推导蒙特卡洛均值的标准误；写出固定种子且多次重复的实验；报告足以复核的随机实验信息；并识别“挑一次最接近真值的运行”这种常见的报告偏差。

## 从一个看似成功的实验开始

程序用随机点估计 $\pi$，一次得到 `3.1416`，于是作者宣布算法正确。但换一个种子可能得到 `3.11` 或 `3.17`。这种变化未必是 bug：随机模拟本来就在估计量的分布中取一次样本。问题不在于某一次离真值多远，而在于它的误差是否与样本数、随机源和理论不确定性一致。

可复现的科学计算也不是把 seed 永远固定为一个幸运数字。固定 seed 让具体失败可重演；多个预先声明的 seed 让结果暴露抽样波动；保存输入、版本和统计量让别人能判断结论是否可信。

## 从伯努利变量推导抽样误差

在单位正方形 $[0,1]^2$ 均匀抽点，定义

$$I_i=\mathbf1\{X_i^2+Y_i^2\le1\}.$$

点落入四分之一圆的概率为 $p=\pi/4$，故 $I_i\sim\operatorname{Bernoulli}(p)$，且

$$\hat\pi=4\bar I=\frac4N\sum_{i=1}^N I_i.$$

线性性给出 $E[\hat\pi]=4p=\pi$；若样本独立，

$$\operatorname{Var}(\hat\pi)=\frac{16p(1-p)}N,
\qquad \operatorname{SE}(\hat\pi)=4\sqrt{\frac{p(1-p)}N}.$$

标准误按 $1/\sqrt N$ 缩小：要将典型抽样误差减半，通常需四倍样本。这个误差来源于有限随机样本，即使使用精确实数算术仍会存在；浮点误差是另一条链路，不能混为一谈。

## 可运行实验：重复运行而非挑选一次

错误博物馆的模拟模块运行同一算法、不同预先指定种子，并报告重复运行的样本标准差和均值标准误：

```python
from projects.floating_point_museum.simulation import simulation_report

report = simulation_report(10_000, seeds=(2026, 2027, 2028, 2029))
print(report)
print("报告含 runs、samples_per_run、mean、sample_std、standard_error")
```

```bash
python -m unittest projects.floating_point_museum.test_simulation
```

若重复估计值为 $z_1,\ldots,z_R$，则

$$s=\sqrt{\frac1{R-1}\sum_{r=1}^R(z_r-\bar z)^2},\qquad
\operatorname{SE}(\bar z)\approx\frac{s}{\sqrt R}.$$

这里 $s$ 描述不同运行间的散布；$s/\sqrt R$ 描述报告均值的抽样不确定性。只有一次运行时，无法从运行间数据估计 $s$，项目明确返回零作为“未估计”的占位值，而不是把它误解为实验没有不确定性。

## 算法、复杂度与正确性

每次抽样做常数次随机数生成、乘法和比较，时间 $O(N)$、额外空间 $O(1)$。`estimate_pi` 固定使用局部 `Random(seed)`，因此相同 `(N, seed)` 产生相同序列；它不会污染全局随机状态。`simulation_report` 对每个 seed 调用一次估计，再按定义计算均值与样本标准差。

正确性不等于某次接近 $\pi$：指标函数的期望证明估计量无偏；独立抽样假设给出方差公式；测试验证种子可重复、输入合法性与报告字段。若随机数产生器、抽样分布或代码实现不满足这些前提，代数推导便不再保证结论。

## 三类误差不要混报

| 来源 | 改变什么 | 常用诊断/缓解 |
| --- | --- | --- |
| 抽样误差 | 换 seed 或重复运行会波动 | 增加样本、重复运行、报告标准误/区间 |
| 浮点舍入 | 同一数值表达式可能积累或消去误差 | 稳定算法、缩放、残差与高精度对照 |
| 系统/建模偏差 | 所有重复运行可能稳定地错 | 审查抽样分布、独立性、单位与基准 |

例如这里的 $I_i$ 只有 0 和 1，求和的浮点舍入通常极小；若改为累积重要性权重或长时间轨迹，浮点累加就可能成为主要误差，需结合 [Kahan 求和](/numerical-computing/kahan-summation) 和对数域计算。

## 失败案例与工程边界

- **选种子**：先跑一百个 seed、只报告最接近真值的一次，会制造虚假的精度。
- **伪重复**：同一随机流切成相邻片段未必独立；并行程序还可能因调度改变序列。
- **只固定 seed**：可复现单次输出，却无法衡量抽样不确定性；应固定一组 seed 或记录生成规则。
- **把 Python 伪随机数用于安全任务**：这里的 `Random` 用于教学模拟，不适合密钥、令牌或对手模型。
- **忽略版本与硬件**：不同库、编译器、并行归约顺序可能改变浮点轨迹；高要求实验应记录环境和依赖版本。

## 常见误区

1. “样本数翻倍，误差就减半。”错误：典型标准误约按 $1/\sqrt N$ 降低。
2. “固定 seed 就足够严谨。”错误：它解决可重演，不替代重复运行与不确定性报告。
3. “结果波动说明算法错误。”错误：先与理论标准误和输入分布比较。
4. “重复很多次便没有偏差。”错误：重复只缩小随机误差，不能消除错误的模型或抽样分布。

## 练习

1. **基础题**：由 $I_i\sim\operatorname{Bernoulli}(p)$ 推导 $\operatorname{Var}(\hat\pi)$。
2. **推导题**：证明样本数从 $N$ 增至 $4N$ 时理论标准误减半；说明这依赖哪些独立性假设。
3. **编码题**：为 `simulation_report` 加入置信区间近似，并测试一个 seed 与多个 seed 的边界语义。
4. **开放题**：设计一个并行蒙特卡洛实验的复现记录：包括随机流拆分、版本、硬件、样本数和停止准则。
