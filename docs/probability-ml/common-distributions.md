# 常见分布如何建模现实

## 学习目标

读完后，你能把“数据长得像什么”改写成可检验的生成假设；能从独立试验推出二项分布、从泊松过程推出指数等待时间；能用均值—方差关系和最小代码发现模型不适配。

## 从一个建模错误开始

运营同学说：“每分钟收到 8 个请求，所以每一分钟一定是 8 个。”这把**平均速率**误当成了**确定结果**。另一个常见错误是看见钟形直方图就套正态分布，却忘了次数不能为负、用户请求也未必独立。

分布不是数据的标签，而是一组关于产生数据的机制。选择分布前先回答：一次观测是二元结果、固定次数的计数、固定时间窗的到达数，还是下一次到达的等待时间？

## 五种最常用的生成机制

| 分布 | 随机变量 | 生成假设 | 参数与均值方差 |
| --- | --- | --- |
| 伯努利 | 一次成败 $X\in\{0,1\}$ | 一次试验成功概率固定 | $p$；$E[X]=p,\operatorname{Var}(X)=p(1-p)$ |
| 二项 | $n$ 次中的成功数 | 独立同分布伯努利试验 | $n,p$；$np,np(1-p)$ |
| 泊松 | 时间/空间窗内的事件数 | 独立、均匀、稀疏到达 | $\lambda$；$\lambda,\lambda$ |
| 指数 | 下一事件等待时间 | 泊松过程的相邻到达间隔 | $\lambda$；$1/\lambda,1/\lambda^2$ |
| 正态 | 连续测量误差或总和 | 许多小影响相加且无主导项 | $\mu,\sigma$；$\mu,\sigma^2$ |

这里的 $\lambda$ 要写清单位：若它是“每分钟 8 个”，则一分钟内计数用 $\operatorname{Poisson}(8)$；等待时间的单位是分钟，均值是 $1/8$ 分钟。

## 从伯努利到二项：组合数为何出现

令第 $i$ 次试验的成功指示变量为 $X_i\sim\operatorname{Bernoulli}(p)$，总成功数是

$$S=X_1+\cdots+X_n.$$

事件 $S=k$ 意味着恰有 $k$ 个位置成功。一种指定的成功/失败排列概率为 $p^k(1-p)^{n-k}$；这样的排列有 $\binom{n}{k}$ 种，故

$$P(S=k)=\binom{n}{k}p^k(1-p)^{n-k},\quad k=0,\ldots,n.$$

期望无需展开这个求和：线性性给出 $E[S]=\sum_i E[X_i]=np$。独立性使协方差为零，因此 $\operatorname{Var}(S)=np(1-p)$。这也解释了为什么二项模型不适用于“抽样不放回”：此时 $X_i$ 彼此相关。

## 泊松计数与指数等待时间

把长度为 $t$ 的时间窗切为许多很短的小段。若每段最多一个事件、事件机会近似独立，且总平均到达数趋于 $\lambda t$，二项分布在“小概率、大次数”极限下成为

$$P(N(t)=k)=e^{-\lambda t}\frac{(\lambda t)^k}{k!}.$$

“等待超过 $t$”等价于前 $t$ 时间内一个事件也没有：

$$P(T>t)=P(N(t)=0)=e^{-\lambda t}.$$

所以 $T$ 的分布函数为 $F_T(t)=1-e^{-\lambda t}$，密度为 $f_T(t)=\lambda e^{-\lambda t}$。并且

$$P(T>s+t\mid T>s)=\frac{e^{-\lambda(s+t)}}{e^{-\lambda s}}=e^{-\lambda t}.$$

这就是无记忆性：已经等了多久不改变剩余等待的分布。人类回复、服务器排队和促销流量通常不满足它。

## 正态分布不是“万能钟形”

若误差是许多相互独立、方差有限且没有单项支配的微小影响之和，标准化后的总和会近似正态。这是中心极限定理提供的**近似理由**，不是“任何数据都正态”的许可。

正态模型尤其应检查：数据是否连续且可取负值、是否存在明显上下界、是否偏态或厚尾、观测之间是否独立。金额、时长、请求计数往往需要对数正态、伽马、负二项或泊松过程等替代模型。

## 可运行实验：用统计量先筛掉错误模型

泊松变量的均值与方差应相近；二项变量的方差不超过均值；独立泊松过程的相邻等待时间应近似指数。下面的函数先做廉价诊断，而非宣称“证明了分布”。

```python
from statistics import fmean

def count_diagnostics(counts: list[int]) -> dict[str, float]:
    if len(counts) < 2 or any(x < 0 or int(x) != x for x in counts):
        raise ValueError("counts 必须是至少两个非负整数")
    mean = fmean(counts)
    variance = sum((x - mean) ** 2 for x in counts) / (len(counts) - 1)
    return {
        "mean": mean,
        "sample_variance": variance,
        "variance_to_mean": variance / mean if mean else 0.0,
        "zero_fraction": sum(x == 0 for x in counts) / len(counts),
    }

print(count_diagnostics([7, 9, 6, 10, 8, 5, 9, 7]))
```

若输出的方差远大于均值，称为过度离散：可能有高低峰时段混合、事件彼此激发，或不同用户群的速率不同。此时强行拟合单个泊松分布，会系统性低估“异常大流量”的概率。

## 算法视角：模型选择的最小流程

```text
确定观测单位（一次试验 / 固定窗计数 / 等待时间 / 连续误差）
写出候选机制的独立性、恒定参数和取值范围假设
用领域知识排除不可能的支持集
估计参数，并比较均值、方差、零值比例与分位数
检查时间依赖、分组差异和极端值；必要时升级模型
```

复杂模型未必更好。若目标是阈值告警，先用能解释且能被持续监控的简单模型；若误判成本高，再做留出集预测检验、似然比较或后验预测检查。

## 失败案例与工程边界

- **把非独立日志当作二项试验**：同一用户连续点击会让方差上升，置信区间过窄。
- **泊松速率随时间变化**：午间与夜间混在一起会产生过度离散；可按时段分层，或使用非齐次泊松过程。
- **正态尾部被低估**：延迟和损失常有厚尾。用平均值加三倍标准差做容量规划可能漏掉真正的峰值。
- **小样本“拟合得很好”**：直方图的形状容易偶然相似。保留新时间段做预测检查，优先问模型能否预测而非能否画出平滑曲线。

## 常见误区

1. “泊松的参数就是每次实验成功概率。”错误：泊松的 $\lambda$ 是一个窗内的平均计数；伯努利的 $p$ 才是单次成功概率。
2. “指数分布的无记忆性适合所有等待。”错误：它是恒定、独立到达的强假设。
3. “均值方差相等就证明是泊松。”错误：这是必要诊断而非充分证明；还需检查取值、独立性与预测表现。
4. “正态近似能让离散和负数问题消失。”错误：近似应检查范围；小计数和尾概率尤其危险。

## 练习

1. **基础题**：一枚硬币抛 $10$ 次，正面概率为 $0.3$。写出恰有 $4$ 个正面的二项概率及其期望、方差。
2. **推导题**：从 $P(T>t)=e^{-\lambda t}$ 推导指数密度，并验证它的无记忆性。
3. **编码题**：为 `count_diagnostics` 加入分时段统计。构造一组“白天速率 10、夜间速率 1”的合并计数，解释为何整体并非好的单泊松模型。
4. **开放题**：为“商品退货所需天数”提出两个候选分布和至少三条可检验假设；说明你会怎样处理未完成退货的截尾数据。
