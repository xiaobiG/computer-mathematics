# 版本迭代看板

这个项目以 Markdown 文章和可运行实验为主体。版本不是文章数量的计数器：只有当读者多获得一条完整、可复跑、可检查的学习路径时，才创建一个版本增量。

## 当前基线：v1.0

当前基线已覆盖五个专题的 75 篇课程文章；每篇课程有学习层级、前置知识、预计时长、至少四道练习及答案提示。核心主题同时要求问题场景、定义或直觉、推导/算法、失败边界和可运行验证。具体覆盖与尚未解决的缺口见[课程成熟度看板](/course-maturity)。

基线质量门禁如下：

```bash
npm run content:check
npm run projects:test
npm run build
```

发布后还需确认 GitHub Pages 中导航可达、内部链接有效且公式由 KaTeX 正常渲染。

## 已完成：v1.1「可信输出」

### 版本问题

现有课程已经能帮助读者推导算法并运行小实验；下一步要回答更接近工程的问题：一个数值或概率输出何时值得相信，输入或计算条件变化时又该如何识别失效。

### 版本范围

| 路线 | 要交付的学习能力 | 计划产物 |
| --- | --- | --- |
| 概率可信性 | 区分排序能力与概率校准，能在独立数据上重新校准模型 | 再校准课程、前后指标对比、可靠性报告 |
| 漂移监控 | 区分协变量、标签与概念漂移；理解告警不是因果结论 | 漂移课程、固定样例、分箱统计和阈值报告 |
| 数值可信性 | 区分残差、后向误差、前向误差与条件数 | 直接法课程、病态系统可视化与可复跑对照 |

### 不在本版本范围内

- 为了数量而扩展新的密码协议或大规模算法专题；
- 与教学闭环无关的全站视觉重构；
- 没有数据契约、反例或测试支撑的“结论型”文章。

## 增量的完成定义

每一个 v1.1 增量都必须同时满足：

1. **课程闭环**：从问题场景到推导，再到失败边界、练习与后续链接；
2. **实验闭环**：输入、参数、随机种子（如适用）、输出指标和结论均可复跑；
3. **证据闭环**：至少有一个应当失败的反例、相应的自动化测试或独立重放检查；
4. **站点闭环**：文章已进入专题导航，并通过全部构建门禁。

后续版本提交在提交信息和变更说明中记录以下字段：

若一个改动不能明确回答这些问题，就先作为草稿或问题记录，而不冒充一次版本发布。

## 已完成：v1.2「图算法对照实验室」

### 版本问题

离散数学已有 BFS、Dijkstra、Bellman–Ford 与 Floyd–Warshall 的独立课程和证书，但读者仍难在同一张图、同一条轨迹上判断各算法的适用边界与计算代价。

### 版本范围

| 路线 | 要交付的学习能力 | 计划产物 |
| --- | --- | --- |
| 同图对照 | 在无权、非负权、含负边、负环四类图上选择正确算法 | 可编辑小图、算法结果/轨迹并列报告 |
| 不变量对照 | 区分 BFS 分层、Dijkstra 定型、Bellman–Ford 按边数松弛、Floyd 中间点集合 | 同一输入下的状态解释和可重放证书 |
| 复杂度边界 | 用顶点数、边数、源点数和稠密度选择算法 | 小规模实测与理论复杂度报告 |

### 不在本版本范围内

- 把教学图编辑器包装成通用图数据库或生产路径规划器；
- 引入没有可复跑验证的动画；
- 脱离既有 BFS、Dijkstra、Bellman–Ford、Floyd–Warshall 学习路径的随机新主题。

## 正在推进：v1.3「带标签窗口下的性能退化审计」

### 版本问题

现有概率专题可用 PSI/总变差发现输入漂移，也可做概率校准；但标签往往延迟到达。读者还缺少一条可重放学习链：当一个带标签窗口到达时，如何区分输入变化、分类性能退化和概率承诺失真，并声明样本量与结论边界。

### 版本范围

| 路线 | 要交付的学习能力 | 计划产物 |
| --- | --- | --- |
| 带标签窗口合同 | 固定参考/当前窗口、类别、预测分数和延迟标签的口径 | 规范化输入、重放报告与篡改证书 |
| 性能退化 | 同时审计错误率、对数损失、混淆矩阵和不确定性 | 课程、可运行项目、浏览器内窗口对照 |
| 决策边界 | 区分“统计信号”“需要复核”和“自动行动” | 阈值说明、反例和测试 |

### 不在本版本范围内

- 自动重训、自动部署或任何生产风险决策；
- 将有限教学窗口的统计量解释为因果结论；
- 没有独立重放与失败反例支撑的性能声明。
